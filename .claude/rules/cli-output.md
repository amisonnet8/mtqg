# CLI出力

仕様の正は `docs/reference/cli.md`。理由は設計§10.5、§10.6、CLI設計§5。

## 言語

- **mtqg自身が出す文言は英語。** エラー、案内、確認、見出し、列名、結果の表示、`--help`、`context`の冒頭の指示文が対象
- **利用者が書いたもの（本文、用語、記録者名）は書いた言語のまま。** 翻訳も制限もしない。日本語で使う人の画面は「枠は英語、中身は日本語」になる
- 多言語化の仕組みは持たない
- 対話（Claude Codeとのやり取り）は日本語だが、コード・コメント・CLI出力は英語。混同しないこと

## 文言はCLIの層にまとめる

- コア（`internal/journal/`・`internal/model/`）は文章を返さない。**構造化された結果とエラーの種類**を返す
- 英語の文言にするのは`internal/cli/`だけ。メッセージは1か所にまとめる（段階4でMCP・フックが同じコアを使い、別の出し方をするため）

## 出力の書き方

- `add`系の出力は**作られた記録のIDだけ**（`81e74ef5e8`）。書き込みの速さを邪魔しない
- すべてのコマンドに`--json`を用意する。人間向けの表示とAI向けの`--json`は二重化し、補助ツール（VSCode拡張など）は`--json`を使う
- **`--json`の形は外部との約束。** VSCode拡張は別リポジトリになる見込みで、`--json`だけでつながる。形を変えるときは、先に`docs/reference/cli.md`（と`cli_ja.md`）に書いてから変える。変えるのはフィールドを足すことだけ（読む側は知らないフィールドを無視する）
  - **出力はJSONオブジェクト1つ**（素の配列は返さない。後からフィールドを足せなくなる）。最初のフィールドは`command`。キーは`snake_case`、値のないフィールドは省く（件数は省かない）
  - **IDは常に完全な32桁、時刻はUTC。** `--full-id`は人間向けの表示だけの話。**本文は書かれたまま**（制御文字を置き換えない、幅で切らない、色を付けない）。人間向けの整形（`sanitize`・`truncate`・`formatTable`）を通さない
  - **エラーと警告は、標準エラー出力に1行のJSON**（`{"error":{"kind":...,"message":...}}`、`{"warning":{...}}`）。`--json`のときも標準出力には何も混ぜない。`kind`は機械が見分けるための値で、文言（`message`）は人間向けと同じ。エラーの種類を足したら、`kind`の表を`cli.md`に足す
  - JSONの形は`internal/cli/json.go`に1か所。各コマンドは、記録を`recordJSON`で変換して`emit`するだけにする
  - **`context`の分量の見積もりは文字数からの近似**（ASCII 4文字＝1トークン、ほかは1文字＝1トークン）。トークナイザは依存の基準で足せない。近似であることを仕様に書き、`estimated_tokens`を実際のトークン数のように扱わない
- **`edit`は、本文が今と同じなら何も書かず`Unchanged:`と言う（終了コード0）。** `done`が`Already done:`と言うのと同じ考え方。`delete`は、何を隠したか、一緒に隠れた回答・返信の件数と記録者、行がジャーナルにもgitの履歴にも残ることを必ず言う
- **書く本文がないときは`$EDITOR`が開く**（引数なしの`add`、`q add <id>`・`b add <id>`・`g add <用語>`、本文なしの`edit <id>`）。開く前に、IDが記録に当てはまることを確かめる（長い本文を書いてから断らない）。`edit`は今の本文を入れて開く
- **`undo`が断るのは、`create`の行を消すと他のイベントが記録なしで残るときだけ。** 断るときは何も書かず、いくつあるかを言い、`mtqg delete`を案内する。`status`・`edit`・`delete`の行は消す。何を消したかは（`type`、したこと、本文、ID）必ず言う
- **`review`は、事実を並べるだけで、どれが正しいかを言わない。** 食い違いは対象の名前（種類、ID、本文）まで書く。並行した状態変更は、その記録の状態変更をすべて、時刻・記録者・変更とともに。何もなければ`Nothing to review`。判定はモデル層（`ConcurrentStatusChanges`・`UnattachedReplies`）にあり、CLIは並べるだけ
- **`search`は`log`と同じ行**（新しい順、件数の行は`N records contain "..."`）。当たらなくても成功（終了コード0）。**`format`は、作成の行だけ種類（`question`・`answer`・`bug`・`reply`など）を書き、それ以外の行は`done`・`reopen`・`edit`・`delete`。** `.mtqg/`を要らない。**diffの変更なしの行（先頭が空白）は表に出さず、同じ入力にある記録の状態変更・削除に本文を貸すだけ**（`git show`で、そのコミットで書かれていない行が混ざらないように）
- **`archive`は、1行目に解釈した期間（`Range: ...`）を必ず出す。** 続いて`Archived:`（移したものを種類ごとに。削除した記録もその種類として数える。回答・返信も数える。1つもない種類は出さない。何も移さないときは`Archived: nothing`でファイル名を出さない）、`Skipped:`（最後のイベントが期間に入るのに残ったもの。なければ行ごと出さない）。`-n`は1行目の終わりに`(dry run)`を付けるだけで、あとは同じ。**`-n`は何も書かず、`archive/`も作らない。** 記録者は要らない（`c.reader()`で開く）。範囲の誤りは終了コード2（`usage`）で、`--json`の`kind`を足さない。`--json`は件数だけで、移した記録の一覧は出さない
- 警告（読めない行を飛ばした、衝突マーカーが残っている、など）は**標準エラー出力**へ出す。`--json`の標準出力を壊さないため。件数が多いときは最初の数件と「(N more)」
- **人間向けの表示では、記録に含まれる制御文字を`U+FFFD`に置き換える。** 他人が書いた記録（cloneしたリポジトリの`journal.jsonl`）に端末のエスケープシーケンスが入っていると、`list`が端末の動作を変えてしまうため。`--json`はJSONのエスケープに任せる
- **端末に出すときだけ**、端末の幅に合わせて本文を`...`で切る。パイプやファイルには切らずに出す（AIが読む出力から情報を落とさない）。桁は**表示の幅**で揃える（全角は2列。`golang.org/x/text/width`）
- 終了コードは、0：成功（すでに済んだ変更も含む）、1：頼まれたことができなかった、2：コマンドラインの誤り
- 時刻はローカル時間で表示する（データはUTC）
- IDは**先頭10桁**で表示する。`--full-id`で完全な32桁を表示する
- IDの入力は、**4桁以上**で一意に決まる前方一致を受け付ける（3桁以下はエラー。`add`・`bad`のような語をIDと取り違えないため）。複数に当てはまるときは、止まって、候補を**完全なID**で並べる（利用者がそこから好きな長さを写して打ち直せるように）
- 一覧で先頭10桁が重なって同じに見えるのは、まれな場面として割り切る（`--full-id`で見分ける）。表示の桁を自動で伸ばす仕組みは作らない
- **`show`は本文を全文で出す**（端末でも切らない。複数行も全行）。制御文字の置き換えは一覧と同じ。切るのは一覧・`log`の1行の本文だけ
- **`qa list`・`bug list`は、質問・バグの下に最新の回答・返信を1件、字下げして出す。** 状態は末尾の列に書く（質問は`unanswered`、`N answers, awaiting confirmation`、`N answers, done`、`done without answers`。バグは`no replies`、`N replies, ...`、`done without replies`）。色だけで意味を伝えない
- **`q add`・`b add`の最初の引数が16進数4桁以上で当てはまる記録がなければ、新しい記録にせずエラーにし、質問（バグ）にしたいなら全体を引用符で括るよう案内する。** 黙って新しい質問やバグができる事故を止めるため（設計§4.5）。文言は`messages.go`。質問と返信・バグと返信の判定は同じ1か所のコード（`thread.go`）で、種類ごとに実装を分けない
- 色は端末が対応していれば付ける。`--no-color`と`NO_COLOR`で消せる。**色だけで意味を伝えない**

## 正直に伝える

- 削除は「表示から除外した。gitの履歴には残る」ことを必ず伝える（設計§2.5、§8）
- 質問を消して回答も一緒に隠れるときは、そのことと、誰の回答かを伝える
- `undo`・`archive`は、何を取り消した・移したかを必ず表示する
- `archive`は、期間をどう解釈したかを必ず1行目に表示する（入力を寛容にしているため）
- `init`はコミットしない。「`.mtqg/`をコミットしてください」と案内するだけ

## `context`の書き方

- Markdownの見出しと箇条書き。IDを必ず添える（AIがそのまま`show`や`done`に使える）
- 省略するときは件数と見る方法を書く（`(7 more; see mtqg log)`）。`...`だけにしない
- 食い違いは対象の名前まで書く
- 「未コミット」は主語を明示する（コードの変更と誤読されるため）
- 空の区画は出さない
- プロジェクトの説明・現在の仕様・ビルド手順は入れない。それはREADMEや指示ファイルの役目
