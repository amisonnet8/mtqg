# ジャーナル（データ形式）の扱い

`.mtqg/journal.jsonl`はmtqgの記録そのものであり、**利用者のリポジトリにコミットされ、他の人や他のAIが読む**。ここでの間違いは、コードのバグと違って利用者のデータに残り続ける。データ形式に触れる作業では、このファイルを必ず踏まえること。

仕様の正は **`docs/reference/schema.md`**。理由は設計§5〜§7、§9.1。

## 変えてはいけない原則

- **追記するだけ。** 状態の変更・回答・訂正・削除は、すべて新しいイベント行の追記で表す。既存行を書き換える処理を足さない
- **行を消す・移すのは2つだけ。** `undo`（直前の1行を消す）と`archive`（行を`archive/`へ移す）。これ以外に行を消す・移す操作を増やさない
- **読み取り側はファイル内の行順に依存しない。** 並びは`ts`、同時刻なら`id`で決める（unionマージは行順を保証しないため）
- **重複・食い違いはエラーにしない。** 同じイベントが複数あっても結果は同じ。並行した状態変更や用語の重複定義は、どちらが正しいかを決めずに事実として見せる
- **mtqgはアーカイブを見ない。** すべてのコマンドは`journal.jsonl`だけを読む（`archive/`を読むのは、利用者が`mtqg format`にファイルを渡したときだけ）

## 書き込みはジャーナル層だけが行う

- `journal.jsonl`・`archive/`・`version`・`.local/`に書くのは`internal/journal/`だけ（directory-structure.md）
- 呼び出し側は`op`・`type`・`re`・本文など**意味の部分だけ**を渡す。`id`（新規作成時の生成）、`ts`、`author`、`tty`、`v`はジャーナル層が埋める
- **`.mtqg/`の中のファイルは、すべて`os.OpenRoot`で開いた`os.Root`経由で開く**（`Journal.openRoot`）。`os.Root`は、`..`でも、外を指すシンボリックリンクでも`.mtqg/`の外に出さない。mtqgは、他人が作ったリポジトリをcloneした直後に動かされる（AIエージェントが典型）。そのリポジトリが`.mtqg/journal.jsonl`や`.mtqg/.local`を外への向きのリンクとしてコミットしていると、`os.OpenFile`ではリンク先に書き込んでしまう。gosecのG703（利用者が渡したパスでファイルを開く）も、除外を足さずにこれで解消する。`.mtqg/`の中を指すリンクは使える
- ファイルは開きっぱなしにしない。操作ごとに開いて閉じる（Windowsは、開いているファイルを置き換えられないため）

### 追記の手順

1. `.mtqg/.local/lock`にOSのファイルロックをかける（Linux・macOSは`flock`、Windowsは`LockFileEx`。`golang.org/x/sys`経由でcgoなし）
2. `journal.jsonl`に衝突マーカーが残っていないか確かめる。残っていたら書かずにエラー
3. 新規作成なら`id`を生成する（下記「ID」）
4. `journal.jsonl`が空でなく、最後のバイトが改行でなければ、**改行を先頭に足して**書く。途中で落ちて残った書きかけの行に、次の正しい行がくっついて壊れるのを防ぐ
5. `journal.jsonl`に1行を**1回の書き込み**で追記する。追記に`fsync`は付けない（書き込みの速さが最優先）
6. ロックを外す

- ロックのファイルは`journal.jsonl`とは別に持つ。`journal.jsonl`そのものにロックをかけると、`undo`・`archive`の置き換えの後、置き換え前の古いファイルでロックを待っていたプロセスが、消えたファイルに書き込んでしまう
- ロックのファイルを一時ディレクトリ（`os.TempDir()`）に置かない。シンボリックリンクや大文字・小文字の違いで同じ`.mtqg/`が別の名前になり、排他が効かなくなるため。`.mtqg/.local/`ならどのパスでたどっても同じファイルになる
- gitの`index.lock`のような「ロックファイルを作れたら持ち主」方式は使わない。強制終了でロックが残るため（mtqgはAIエージェントごと止められることが普通にある）
- ロックが取れないときは**5秒**待ち、それでも取れなければエラー。`flock`は待ちを中断できないので、ロックを非ブロッキングで試して、数msから50ms程度の間隔で再試行する
- ロックのファイルは消さない（消すと、別のファイルにロックをかけた者どうしで排他が効かなくなる）。`.mtqg/.local/`が無ければ作る（cloneした直後は無い）

### 書き直し（`undo`・`archive`）

- 同じロックを取り、全行を渡して変更後の行を受け取り、**一時ファイルに書いてから置き換える**
- 一時ファイルは`.mtqg/.local/tmp/`に作る（置き換えを一瞬で終わらせるため、`journal.jsonl`と同じファイルシステムに置く必要がある。`.local/`ならコミットもされない）。置き換える前に`fsync`する
- ロックなしで書き直すと、書き直し中に別プロセスが追記した行が消える
- **行は元のバイト列のまま書き戻す。** 知らないフィールドも、読めなかった行も、手で直した整形も消えない。消えるのは、呼び出し側が返さなかった行だけ（読み込みと違い、内容が同じ行も1つにまとめない）
- Windowsは、開いているファイルを置き換えられないことがある。自分のハンドルは置き換える前に閉じ、読み込み中の別プロセスに備えて、上限を決めて短く再試行する

## 書き出し規則

- Goの構造体にフィールドを決まった順で並べ、`encoding/json/v2`のエンコーダで書く。**独自の整形処理を書かない**。JSONを扱うのは`internal/journal/event.go`だけ
- キーの順：`id, op, type, re, from, status, word, text, at, v, ts, author, tty`（`author`の中は`kind, name`）
- 値がないフィールドは`null`を書かず**省く**
- 日本語などをエスケープしない。`<`・`>`・`&`も、U+2028・U+2029もエスケープしない。**`encoding/json/v2`を使う理由：** v1は、`SetEscapeHTML(false)`にしてもU+2028・U+2029を常にエスケープし（規則に反し、他のツールが規則どおりに書いた同じイベントと行が食い違う）、不正なUTF-8を黙って`U+FFFD`に置き換える（データの破壊）。v2は既定で必要最小限のエスケープだけで、不正なUTF-8はエラーにする。既定に頼らず、`jsontext.EscapeForHTML(false)`・`EscapeForJS(false)`を明示する
- **不正なUTF-8の本文は書かずにエラーにする。** 黙って置き換えない
- **すべての行をLFで終える**（ファイル末尾も改行）。unionマージとアーカイブの戻し（`cat >>`）がこれに依存する
- 時刻（`ts`）はUTC、`2026-09-17T01:32:00Z`の形。表示のときにローカル時間へ直す
- **読むときは寛容に。** キー順・空白・エスケープの違いを問わず、正しいJSONなら読む。重複キーは受け付ける（`jsontext.AllowDuplicateNames(true)`、最後の値が勝つ）。キー名の大文字小文字は区別する（v2の既定）。**不正なUTF-8の行、`id`か`op`が無い行は、警告して飛ばす**（元のバイト列は書き直しで保たれる）

## 形式のバージョン

- 今は**形式0（未確定）**。`.mtqg/version`も各行の`v`も`0`で書く。v1確定まで、形式の変更で`version`を上げない
- 形式0の間は形式を自由に変えてよい。ただし**変えるときは、先に`docs/reference/schema.md`（と`schema_ja.md`）を更新してから**実装する
- 読むときに`version`が自分の知る番号より新しければ、読み書きとも断る
- v1以降のルール（知らないフィールドは無視してよい変更では番号を上げない、意味が変わる変更は上げる、`mtqg upgrade`でだけ上げる）は`schema.md`の「Versioning」にある。v1確定前でも、この区別を意識してフィールドを足すこと

## SCHEMA.md

- `.mtqg/SCHEMA.md`は、`docs/reference/schema.md`をルートの`schema.go`で埋め込み、`mtqg init`が書き出したもの。**`schema.md`が唯一の元**
- `schema.md`は、mtqgを使うプロジェクトで初見の人やAIが読む文書でもある。mtqg本体の開発事情（層の名前、段階など）を書かない

## ID

- 新規作成時に、`crypto/rand`でUUIDv4を作り、**ハイフンを除いた小文字の16進32桁**で書く。IDのための調整（採番、カウンタ、ロック中の確認）は何もしない
- 保存するデータ（`id`、`re`）は常に完全な32桁。**短縮は表示と入力だけ**（先頭10桁の表示、前方一致の受け付け・cli-output.md）
- 完全なIDの衝突は考えなくてよい（そのための処理を書かない）

## ローカルの状態（`.mtqg/.local/`）

- このマシンでだけ意味を持つ一時的なもの（`lock`、書き直しの一時ファイルの`tmp/`、段階4のフックで必要になった場合の`sessions/`）を置く
- `mtqg init`が`.mtqg/.gitignore`に`.local/`の1行を書く。**コミットされない**
- **いつ消えても困らないものだけを置く。** ロックは次に書くときに作り直し、`tmp/`の残骸は書き直しの途中のものなので消してよい。他の読み手が必要とする情報や、消えると記録の意味が変わる情報を置かない
- gitの私的な領域（`git rev-parse --git-dir`の先）には何も置かない。mtqgの状態はすべて`.mtqg/`の中に収まる
