# テスト方針

理由は設計§10.10。

## 開発環境の前提

開発者の手元環境は**Linux（devcontainer）のみ**。Windows・macOSでの動作確認は手元では行わず、GitHub Actionsのホステッドランナーに委ねる。

| 対象 | 進め方 |
| :--- | :--- |
| コア（ジャーナル層・モデル層） | Linux・Goだけで開発し、ロジックの正しさを固める。フィードバックを最速に保つ |
| クロスプラットフォーム（Windows・macOS） | 開発初期からGitHub Actionsの3OSマトリクスで回す。**ロックの実装がOSで分かれる**（`flock`と`LockFileEx`）ため、後回しにしない |
| 依存の脆弱性・ライセンス | `trivy`（下記） |
| シェルスクリプト | `shellcheck`（下記） |
| シェル補完（bash・zsh・fish・PowerShell） | 4つとも**devcontainerに入れてある**（`postCreate.sh`。pwshはLinux版）。補完スクリプトは本物のシェルで動かして確かめる（下記「シェル補完」） |

## 実装後の動作確認

実装したら、ビルド確認に加えて実際の動作確認を行うこと。ロジック上正しそうに見えても、動かして初めて見つかる不具合はある。

- `qsoku check`（fmt・vet・lint・単体テスト）は作業の区切りで必ず通す
- e2e（`qsoku test`）を走らせる粒度は作業規模で判断する
  - 小規模な修正（数行、1関数内）は、一連の作業の最後に1回でよい
  - 複数ファイルにまたがる変更、ジャーナル層・ロック・マージに関わる変更は、各ステップの区切りごとに実行する
  - 迷ったら実行する側に倒す

## Goのテスト

- コア（ジャーナル層・モデル層）は**表示と切り離して単体でテストする**
- 一時ファイル・ディレクトリは`t.TempDir()`で作る。作成も後片付けもテストの仕組みに任せ、`rm -rf`で片付けない
- gitを使うテストは**本物の`git`コマンド**で一時リポジトリを作る。gitの動きを模したものに置き換えない
- テスト内のgitは、開発者の設定の影響を受けないようにする。`HOME`と`GIT_CONFIG_GLOBAL`を一時ディレクトリに向け、`user.name`・`user.email`はテスト内で設定する（`t.Setenv`）
- **期待値の件数・ID・桁は、手で書かずに、実際の出力を読んで正しいと確かめてから固定する。** Step 5で、手で数えた「記録11件」と、写し間違えた質問IDが、正しい実装の出力と食い違った。テストが落ちたときは、実装と期待値のどちらが間違っているかを、出力を読んで判断する（貼るだけにしない）
- **`Run`を直接呼ぶテストで、`Env.Now`が効くのは表示だけ。** ジャーナルに書かれる`ts`は、ジャーナル層の本物の時計（`Journal.now`）から入る。書いた行の`ts`を固定値と比べるテストは書けない（正規表現で形を確かめる。時刻の並びを確かめたいときは`setJournal`で行を用意する）。Step 6で、`edit`の行の`ts`を`Env.Now`の値と比べて落ちた
- **「まだ作っていないコマンド」（`run`が無いコマンド）のテストは、実在のコマンドに頼らず、テストの中で`commands`に仮のコマンドを足して書く。** Step 6で`undo`を作ったとき、それを使っていた3か所（`commands_test.go`・`json_test.go`・`e2e_test.go`）が落ちた。Step 7で`archive`を作って未実装のコマンドが無くなったので、仮のコマンドを`t.Cleanup`で戻す形にした（このパッケージのテストは`t.Parallel`を使わない）。e2eは本物のバイナリに仮のコマンドを足せないので、このケースを持たない（`run == nil`の扱いは単体テストの担当）
- **gosecのG602（添字の範囲）は、除外を足さず、添字を使わない書き方にして解消する。** 「見つけた最良の行の添字」を持ち回る代わりに、その行の時刻を持ち回った（`model/undo.go`）
- ロックは、複数のgoroutine・複数のプロセスから同時に書いて、行が欠けないこと・混ざらないことを確かめる。書き直し（`undo`・`archive`）と追記を同時に走らせても行が消えないことも確かめる
- **壊して確かめる手順は、Skill `mutation-check`（`.claude/skills/mutation-check/`。`mutate.sh`が、変異を入れて、テストを走らせ、必ず元に戻す）。** Step 7・8・9で、同じ手順を毎回その場で書いていたので固定した。生き残った変異は、握りつぶさずに読み、テストを足すか、同じ意味だと理由を書いて残す。
- **並行・排他のテストは、壊して確かめる。** ロックを無効にする（`tryLock`が常に成功する、`Rewrite`がロックを取らない）変異を手で入れ、テストが失敗するかを一度見て、元に戻す。追記どうしの並行は、`O_APPEND`のおかげでロックなしでも通ってしまう。排他を直接確かめるテスト（待ち時間切れ、保持者を`Kill`する、シンボリックリンク経由）と、追記と書き直しの並行テスト（ロックを外すと120行中33行しか残らない）が、ロックの有無を区別する。通るだけのテストは、効いているとは限らない
- **並行テストには「証明にならない」ガードを入れる。** 書き直しが3回未満なら失敗にする、など。ロックは公平ではない（`lock`のコメント）ので、休みなしで追記し続けると書き直しが締め出され、テストが何も確かめないまま通る（実際に`-race`で1回だけ失敗した）。追記の合間に短い休みを入れて、実際の使い方（短いコマンドの間に休みがある）に近づける
  - **ガードを入れるだけでは、実行時間を縮めたときに間欠的に落ちる**（Step 7で、`archive`のテストの追記の回数を減らしたら、10回に2回、アーカイブが1回しか重ならず落ちた）。**追記の側を「決めた回数」でなく「書き直す側が必要な回数を終えるまで続ける」形にする**と、ロックの分け方に関わらず、必ず重なる。書けた行数を数えておき、あとで期待値にする
- 別のプロセスから書くテストは、テストバイナリ自身を`os.Args[0]`で再実行するヘルパー（`TestHelperProcess`、環境変数で動作を切り替える）で書く。シェルスクリプトは使わない
- 並行テストは、`-count=10`や`qsoku race`の繰り返しで、たまにしか落ちないことを確かめてから区切りにする
- **Goのソースに、見えない文字（ゼロ幅、U+2028・U+2029、文字の向きを変える制御文字、制御文字）を、そのまま書かない。** エスケープ（`\xe2\x80\xa8`のバイト列、または数値）で書く。`\uXXXX`と書いたつもりが、書き込みの途中で実際の文字に展開されていたことがあり（`internal/journal/event_test.go`にU+2028が入り、JSONのエスケープを読むテストの入力が普通の文字に変わっていた）、gosecのG116が検出した。ルートの`source_test.go`が、すべての`.go`を検査する（最初の草稿の、自分自身のコメントも検出した）。文字の範囲を書くときも、数値で書く

## mtqg固有の検証項目

単体テストでは確かめにくい、**複数のクローンやブランチをまたぐ動き**がmtqgの設計の芯である。e2eで押さえること。

**Step 8で、この一覧の項目はすべてe2eにある**（`e2e/`）。対応：unionマージと行順・両ブランチが同じ質問に答える・同じtodoを別々に閉じる（`e2e_test.go`）、衝突マーカー（読みは警告・書きは拒否、消せば正しく読める）・知らない`version`・`.mtqg/.local/`を消しても動く・submodule・既存`.mtqg/`への`init`（`boundaries_test.go`）、worktreeとシンボリックリンクのロック（`lock_unix_test.go`。テストがロックを握って、別のmtqgが待つかを見る。**LinuxとmacOSだけ**で、WindowsのLockFileExはジャーナル層の別プロセスのテストが担当する）、曖昧なID・種類の取り違え・`edit`・`delete`・`search`（`records_test.go`）、`archive`の各項目（`e2e_test.go`）。壊して確かめた変異：追記が衝突マーカーを無視する、新しい形式を受け入れる、`.local/`を作り直さない、ロックが待たない、曖昧な前方一致が最初の1件を選ぶ、質問を消しても回答が残る、3桁のIDを受け入れる（すべてe2eが検出）

- 2つのクローン（またはworktree）でそれぞれ記録し、マージして両方の記録が残る（unionマージ）
- unionマージ後に行順が混ざっても、状態が正しく組み立てられる
- `.gitattributes`のマージ指定が効かない形で衝突させ、衝突マーカーがある状態で「読み込みは警告、書き込みは拒否」になる
- 衝突マーカーを消して両側を残せば、正しく読める
- 同じ`from`から別々に状態を変えると`review`に出る
- `archive`した後、archive前に分岐していたブランチをマージしても壊れない。`archive/`のファイルを`cat >>`で戻すと元どおりになる
- worktreeを追加しても、それぞれの`.mtqg/.local/`で排他が分かれ、互いに干渉しない
- `.mtqg/.local/`を消しても、次のコマンドが正しく動く（ロックと`tmp/`を作り直す）
- 同じ`.mtqg/`を別のパス（シンボリックリンク経由など）から開いても、同じロックで排他される
- 前方一致が曖昧なIDを渡すと、候補を完全なIDで並べて止まる
- 種類の取り違え：`qa`と`bug`のIDを取り違えると（`b add <質問id>`、`q add <バグid>`、返信への返信、`q done <バグid>`）、どの向きでもエラーで止まり、`journal.jsonl`には何も書かれない。正しいコマンドがあるときは案内される。種類をまたぐ`re`の行（他のツールが書く）は、エラーにせず、返信先のない記録として読む（モデル層のテスト）
- `--json`：どのコマンドも、標準出力にJSONオブジェクト1つ（最初のフィールドが`command`）。エラーと警告は標準エラーに1行のJSONで、標準出力は空のまま。`--full-id`・`--no-color`・端末の幅で出力が変わらない。本文は書かれたまま（制御文字を置き換えない、切らない）。壊して確かめる変異：本文を`sanitize`する、IDを10桁にする、エラーを標準出力へ出す、時刻をUTCでなくする
- `context`：予算に収まる、削る順序が仕様どおり、空の区画を出さない、削ったものを区画の中で言う。**削る順序は、予算を少しずつ下げながら、後の削りが先に起きないことを不変条件で確かめる**（「この予算ならこうなる」という数字を固定すると、文言を1つ直すたびに壊れる）。予算を無視する、todoを新しい順に削る、定義を残して質問を削る、完了したtodoが混ざる、最新の3件の下限を外す（bugだけ外すのも）、の変異で確かめた。**予算をどれだけ絞っても、最新の3件の質問とbugが残ること**も確かめる
- `undo`：**行を消す唯一のコマンドなので、消えてはいけないものが消えないことを確かめる。** 別の端末（`MTQG_TTY`を変える）・別の記録者の行が消えない、端末のない行（パイプ越しのAI）と端末のある行が互いの対象にならない、同じ秒の2行で後に書いたほうが消える、`create`を消すと他のイベントが記録なしで残るときは断って`journal.jsonl`が1バイトも変わらない、`status`・`edit`・`delete`の行は後に何があっても消える、同じ内容の行は全部消える、他の行は元のバイト列のまま残る。壊して確かめる変異：端末を見ない、記録者を見ない、宙に浮く判定をしない、同じ秒を`id`で決める
- `edit`・`delete`：`edit`が本文だけを変える（`word`・状態は変わらない）、同じ本文なら何も書かない、`$EDITOR`に今の本文が入る、`delete`が質問・バグの回答・返信を隠す（件数と記録者を言う）、回答だけ消しても質問の状態は変わらない。変異：`edit`が`word`も書き換える、`delete`が回答を隠さない
- `review`・`search`・`format`：**並行した状態変更の判定は、正しい順番の変更（`open→done→open→done`）を誤検出しないことと、本当の並行を検出することの両方を確かめる**（同じ`from`が2つ、という判定は前者を誤る）。`from`のない行は判定しない、同じ行の繰り返しは食い違いでない。`search`は大文字小文字を区別しない・用語も探す・見える記録だけ。`format`は`git show`の出力を丸ごと渡されても落ちない・時刻順に並べる・`-`の行に印を付ける。変異：`from`を見ず件数で判定する、`search`が大小を区別する、`format`が時刻順に並べない
- `tty`：`Env.TTY`と`MTQG_TTY`から作った値が、同じ端末なら同じ、別の端末なら別になる。e2eは`MTQG_TTY`で端末を作り分ける（Windowsのランナーでも動く）。デバイス番号からの`tty`は、Linux・macOSで、標準入出力が端末のときだけ値を持つ（CIには端末がなく、テストできないので、手で確かめる）
- `archive`：**行を移す2つ目のコマンドなので、行が失われないことを確かめる。** 移した行がアーカイブに元のバイト列のまま入り、残る行も元のバイト列のまま、移した行と残した行を合わせると元の行の全部になる、`cat archive >> journal.jsonl`で元の状態に戻る、読めなかった行は移らない、`-n`は1バイトも書かず`archive/`も作らない、移す行が0なら`archive/`を作らない、衝突マーカーがあれば何も書かない、`移す＋残す`が合わなければ何も書かない。期間は両端の日を含むこと（ローカルの日付）、質問・バグは回答・返信の日付まで含めて判定すること、削除した記録は種類を問わず移ること、未完了のtodo・質問・bugとglossaryは移らないこと、親のない返信はmemoと同じに扱うこと。アーカイブと追記を同時に走らせても行が消えない。壊して確かめる変異：終了日を含めない、UTCで判定する、未完了のtodoも移す、glossaryも移す、回答を親と一緒に移さない、回答の日付を見ない、削除した記録を移さない、`-n`が書く、読めなかった行も移す、行数の検査を外す。**移す順序（先にアーカイブへ追記、あとで`journal.jsonl`を置き換える）は、書き込みを失敗させて確かめる**：`archive/`を書き込み不可にすると`journal.jsonl`は変わらず、`.local/`を書き込み不可にすると（一時ファイルが作れず置き換えが失敗する）行がアーカイブにもある、の両方を見る（順序を逆にする変異はこれで検出される。root と Windows では権限が効かないのでskip）。**e2eは、片方のブランチがアーカイブし、もう片方が隣の行を変えてマージすると、行が`journal.jsonl`に戻ることがある**（失われはしない）ので、「行が失われない」「衝突マーカーがない」「もう一度アーカイブすれば片付く」を確かめ、戻るか戻らないかは決めつけない
- **シェル補完（Step 9）：候補は`mtqg candidates`が決め（`internal/cli/candidates_test.go`）、スクリプトが行をそのまま渡すことは本物のシェルが確かめる（`e2e/completion_test.go`）。** 単体テスト：位置ごとの候補の表（1語目、種類の次、オプション、`--kind`の値、ID）、**表との一致**（`commands`のすべてが1語目に出る、`optionsAt`のオプションと`parseArgs`が受け付けるものが両方向で一致する、IDを取るコマンドは`ids`を持つ）、何があっても黙って0で終わる（`.mtqg/`が無い、形式が新しすぎる、衝突マーカー、読めない行、`-C`が存在しない）、説明の切り詰め・制御文字・全角、10桁が重なるIDは完全なID。e2e：**同じ13行を4つのシェルに打たせ、出るものが同じであること**（順序はシェルが決めるので、並べ替えて比べる）。bashは`COMP_WORDS`・`COMP_CWORD`を組んで`_mtqg`を呼ぶ。fishは`complete -C`。PowerShellは`TabExpansion2`（登録した補完がそのまま効く）。zshは補完のしくみが端末を要るので、`words`・`CURRENT`を組んで`_mtqg`を呼び、`_describe`の代わりの関数が受け取るものを読む（`zsh -n`の構文検査も）。1つのシェルにつきプロセスは1回（pwshは起動が0.5秒かかる）。**シェルは、無ければskip、あるのに本物のmtqgを動かせなければ失敗**（何も確かめずに通るのを避ける。Windowsの`bash`はWSLの起動用のものになりうるので、Git for Windowsのbashを探す）。壊して確かめた変異（すべて検出）：候補が前方一致で絞らない、`done`が完了済みも出す、古い順、10桁の重なりを見ない、10桁より長く打っても10桁で出す、本文の途中でオプションを出す、`-n`と`--dry-run`を別に数える、`-C`の値を読まない、説明を切らない・制御文字を置き換えない、警告を出す、短縮形の1文字を出す、未実装のコマンドを出す、`--mark`を出さない、パースされないオプションを出す。スクリプト：`--word=`を渡さない、打ちかけの語を語の並びに入れる、`mtqg`自身を語に入れる（4つのシェルとも）。**生き残った変異：**fishで`"--word=$cur"`の引用符を外しても、fish 3.6では通る（空のトークンでも`$cur`は空文字1つで、空のリストにならない）。引用符は残した（空のリストを展開すると引数ごと消えることは確かめた）。**実際のシェルで動かして見つけた不具合：**fishのスクリプトで、語が0個のとき`printf '%s\n' $words`が空行を1つ出し、空の語が1つ渡って「未知のコマンド」になった（`mtqg t<TAB>`が何も出さない）。**確かめていないこと：**対話のシェルでの実際のTAB（bashの`COMP_WORDBREAKS`が`=`で語を切ること、zshの補完のしくみ自体、fish 4系、PowerShell 5.1の引数の渡し方）。**CIで動くシェル：**ランナーの画像にあるものだけ（bash・pwshは3OSにあるはずだが、動くかはCIを見るまで分からない。zsh・fishは無ければskip）。
- **`basis`（段階3。status変更とeditの並行検知）：`internal/model/review_test.go`の`TestBasis`が、edit同士の並行、statusとeditの並行（両方の向き：editが先でstatusが基準を見落とす場合と、statusが先でeditが基準を見落とす場合）、逐次編集（並行でない）は検知しないこと、`basis`が無い古いデータは判定しないこと、`HasState()`でない記録（memo・glossary）のeditも対象になることを確かめる。**`from`と`basis`は独立した信号**（`from`は状態の値の食い違い、`basis`はその記録に起きたこと全部の数の食い違い）で、片方だけでは足りない場面がある：status同士の食い違いは`from`だけで判定でき`basis`は実質何も足さないが、status一つのイベント単独で見ると、`from`は一致するのに`basis`だけが食い違う場面（editが先に起き、それを知らずに書かれたstatus変更）があり、**この場面を確かめるテストが無いと`statusのbasis判定を外す変異が生き残る**（実際に生き残ってから気づいた。テストを足して`TestBasis`に追加）。壊して確かめた変異（すべて検出）：editのbasis不一致を見ない、statusのbasis不一致を見ない、fromの既存判定を壊す、`HasState()`でない記録を素通りする、`seen`を数え違える、`SetStatus`・`EditText`が`basis`を書かない、`append.go`が負の`basis`を受け付ける、`review`の表示がeditを`status`として扱う（`from -> status`と誤表示する）

## e2eとdocsの例の確認

- **例を取るフィクスチャの日付が「今日」のとき、その日の未来の時刻の行が、実際に書く行より「最新」になる。** Step 6で、`q add`のあとの`undo`の例が、フィクスチャにある今日の14:30の行を消した（`undo`は`ts`が最後の行を選ぶ）。書き込んで結果を見せる例（`undo`など）は、フィクスチャではなく、`init`しただけの小さなリポジトリで取る

- e2eは**シェルではなくGoで書く**。`e2e/`に、ビルドタグ`e2e`を付けたGoのテストとして置き、**ビルドした本物の`mtqg`と本物の`git`を`exec`で動かす**（`qsoku test`は`go test -tags e2e`。`qsoku check`には含めない）。`testscript`（`github.com/rogpeppe/go-internal`）は`golang.org/x/`ではないので使わない（依存の基準・`CLAUDE.md`）。**Step 8で「どうしても必要か」を再評価し、要らないと結論した**（docsの例の確認は、下の「文書の例の確認」の印と`-update`で足りる）。`$EDITOR`のように別のプロセスが要るものは、テストバイナリ自身を再実行するヘルパーで書く
- CLIは`Run(env, args)`を直接呼ぶテスト（`internal/cli/`）で細部を、e2eで「本物のバイナリと本物のgitでつながること」を確かめる
- `docs/reference/`などに載せるコマンドの実行例と出力例は、**実際に動かして確かめたもの**にする。**手で書かず、`qsoku docs-examples`（`-update`）が文書に書き戻す**（Step 3〜7で、同じ手作業を6回繰り返し、節ごとに別のフィクスチャを使ったので、文書の中で件数が食い違っていた）

### 文書の例の確認（Step 8。`e2e/examples_test.go`）

- **印：**例のフェンスの直前に、HTMLコメント`<!-- mtqg:example repo=<フィクスチャ> ... -->`を置く。GitHubの表示には出ない。**最初の行が`$ `で始まるフェンスに印が無ければテストが失敗する**（足し忘れを止める）。印の指定は`repo=`（`e2e/testdata/examples/`のフィクスチャの名前、`none`は`.mtqg/`の無いgitリポジトリ）、`ids=any`（新しく作られるIDは比較の前にマスクする）、`path=`（出力に出るリポジトリのパス）、`author=ai:<名前>`、`binary`（本物のバイナリでも同じ出力になることを確かめる）、`setup="<コマンド>"`（その例の前に、見せずに動かすコマンド。前の例が書いた状態が要るとき）、`skip="<理由>"`（理由は必須）。**`$`で始まるブロックは、すべて動かす例。** 使い方の形を並べるだけのブロック（`mtqg archive 2021..2023`など）には`$`を付けない。出力の途中に空行があってよく（`show`・`context`）、コマンドの区切りは次の`$`の行。英語版と日本語版は、例の数・印・コマンドの数が同じでなければ失敗する（片側だけ直すのを止める）
- **`Run(env, args)`を直接呼ぶ。**時計（`Env.Now`）と表示の地域（`Env.Location`）を固定しないと、「今日はHH:MM、それ以前は日付」の表示が実行日ごとに変わって落ちる。`MTQG_NOW`のような、テストのためだけの裏口を製品に作らない。gitは本物。本物のバイナリとの差は`main.go`の`OSEnv`（端末・`$EDITOR`）だけで、例の出力には効かない。**この差が本当に効かないことは、`binary`の印を付けたブロック（時計に依存しない`archive`・`format`の例）を本物のバイナリでも動かして確かめる**
- **フィクスチャは1つの整合したもの**（`parser`・`parser_ja`）から、節をまたいで取る。節ごとにフィクスチャを作らない。例の値が節ごとに食い違うため。書き込む例（`add`・`undo`）は、フィクスチャに未来の時刻の行があると意図しない行が「最新」になるので、`empty`（`init`しただけ）で取る
- **ブロックごとにリポジトリのコピーを作って動かす**（書き込む例が、後続の例に影響しない）
- **出力に出るパスと比べるテストは、一時ディレクトリを`filepath.EvalSymlinks`で解決してから使う。** mtqgが出すのは、リンクと短縮名を解決したパス（macOSは`/var`→`/private/var`、Windowsは`RUNNER~1`→長い名前）。`t.TempDir()`のままだと、`path=`の置き換えが合わず、macOSとWindowsのCIだけで落ちた（Step 8。既存の`newRepo`は同じ理由で解決していた）。**手元（Linux）では、`TMPDIR`をシンボリックリンクにして走らせると再現する**
- **例を実際に動かして取ると、実装の不具合が見つかる。** Step 3で、出力例を取ろうとして、`done`が反映されないことに気づいた（時計が遅れたマシンが書いた変更を、作成より前に並んだという理由で捨てていた）。例は、手で書かずに、動かして貼る
- **例に使う出力は、日時とIDを固定した記録（`journal.jsonl`をフィクスチャとして書いたもの）から取る。** コマンドを続けて打って記録を作ると、`ts`は秒単位なので同じ秒の記録が`id`の順（ランダム）に並び、「最新の回答」や`show`の`Events`が意図と違う並びになる（Step 4で実際に起きた）。これは仕様どおり（`schema.md`の「Reading」）で、不具合ではない。「今日」の記録は`HH:MM`、それ以前は日付で表示される。Step 7まではフィクスチャの日付を実行する日に合わせていたが、今は`Env.Now`を固定するので合わせなくてよい（フィクスチャの「今日」は2026-09-21）
- 英語版（記録の中身が英語）と日本語版（記録の中身が日本語）で例の中身が違うので、確認の対象は両方になる。記録の中身が日本語でも表示が崩れない（桁の揃え、切り詰め）ことの確認も兼ねる

## Trivy：既知の脆弱性とライセンス

- `trivy fs`で、依存モジュールの**既知の脆弱性（CVE）**と**ライセンス**を検査する（`qsoku trivy`）
- mtqgはMITで配布する。**MIT・BSD・Apache-2.0等は許可、GPL・AGPL等の互換性のないライセンスは失敗**にする
- 何を失敗とみなすか（深刻度、禁止するライセンスの種類）は`trivy.yaml`で固定する。HIGH・CRITICALで失敗し、ライセンスはTrivyの既定の分類に従う（forbidden＝CRITICAL、restricted＝HIGHなのでGPL系は失敗、reciprocal＝MEDIUMのMPLや、notice＝LOWのMIT・BSD・Apacheは通る）。分類を上書きするときは理由を`PLAN.md`に記録する
- `go get`で依存を足したら、必ずTrivyを通す。**依存は、Goの標準ライブラリと`golang.org/x/`だけ**（`CLAUDE.md`）。それ以外は「どうしても必要な場合」の例外で、足す前に理由を説明して確認を取り、`PLAN.md`に記録する（`go get`は確認が出る設定になっている）。`x/`に限るので、ライセンスは実質BSD-3-Clauseだけになる
- Trivyは脆弱性データベースの取得に通信が要る
- ソースコード自体のコピペ検出は対象外（人間のレビューに委ねる）

## ShellCheck：シェルスクリプト

- シェルスクリプトは最小限にする。込み入った処理はGoで書く
- `qsoku shellcheck`は`git ls-files '*.sh' '*.bash'`で追跡中のものを列挙して`shellcheck`にかける（新しいスクリプトを足しても`qsokufile`の変更が要らない）。**追跡中のものだけ**なので、`git add`してから走らせる
- 対象：`.devcontainer/postCreate.sh`、`.claude/hooks/`のスクリプト、補完のbashスクリプト（`internal/cli/completions/mtqg.bash`）など。zsh・fish・PowerShellのスクリプトはShellCheckの対象外（e2eで本物のシェルが確かめる）
- **`postCreate.sh`の中で`. /etc/os-release`をsourceしない**（ShellCheckのSC1091が、追える形で指定されていないファイルとして、情報の水準で報告し、終了コードが非0になる）。ディストリビューションの版は`lsb_release -rs`で取る
- CIでは`ubuntu-latest`だけの専用ジョブにする（スクリプトの中身はOSで変わらず、Windowsランナーに`shellcheck`がある保証もない）

**シェルスクリプト中のコメントを、行頭が小文字の`# shellcheck`で始まる文にしてはいけない。** ShellCheckがインラインディレクティブとして解釈しようとし、`key=value`形式でないとパースエラー（SC1072/SC1073）になって、以降の行がチェックできなくなる。「ShellCheck」のように大文字を混ぜて書く。
> **出所:** 別プロジェクト SanDBox で実際に踏んだ事象。

## `-race`の運用

- devcontainerは`CGO_ENABLED=0`（mtqgは純粋なGo・distribution.md）。`-race`はcgoを要するため、`qsoku race`（`CGO_ENABLED=1 go test -race -count=1 ./...`）として`qsoku check`とは別にする
- ロックまわりは並行性のバグが出やすいので、ジャーナル層を触ったら`qsoku race`も通す
- CIでは`race`を別ジョブにし、`ubuntu-latest`・`macos-latest`に限る（`windows-latest`には標準でCコンパイラがない）
> **出所:** 別プロジェクト SanDBox の運用を引き継いだもの。

## GitHub Actions CIの落とし穴

> **出所:** 別プロジェクト（ExecDB・SanDBox）で、初回push後にCI上でのみ顕在化した事象。mtqgも同じ構成（3OSのホステッドランナー）を採るため、あらかじめ対処しておく。

- **`windows-latest`で`qsoku`を`go install`しても、内部で呼ぶ`sh`がそのままPATHに乗るとは限らない。** `qsokufile`のコマンドは常に`sh`（Git Bash付属）で実行される（qsoku自身の仕様）。CIの`run:`ステップは`shell: bash`を明示し、Git Bashが通ったPATHでqsokuを実行する（`.github/workflows/ci.yml`。Makefile時代の`choco install make -y`は不要になった。qsoku自身のバージョンはCI・devcontainerとも`go install .../qsoku@v0.1.1`で固定する。理由・経緯は`docs/design/history.md`2026-09-23）
- **`/dev/stderr`等のUnix固有のパスはWindows（Git Bash）で壊れる。** `tee /dev/stderr`などを使わず、標準のリダイレクトだけで書く
- **Windowsのcheckoutで改行がCRLFになると、`gofmt -l`が全ファイルを未整形と誤検知する。** ルートの`.gitattributes`（`* text=auto eol=lf`）で防ぐ。最初のpush前に置く（配置済み）
- **`uses: owner/repo@TAG`はタグ名と厳密に一致しないと失敗する。** `v`の有無を見落としやすい。書く前に実際のタグ名を確かめる
- **Windowsには実行ビットの概念がない。** `os.Chmod`後に実行ビットを確かめるテストは、`runtime.GOOS != "windows"`でガードする
- mtqg固有の注意：**Windowsでは開いているファイルを置き換え（rename）できないことがある。** 一時ファイル経由の置き換え（`undo`・`archive`）は、Windowsランナーで必ず確かめる
- mtqg固有の注意：**Windowsでは、開いているハンドルのあるディレクトリを消せない。** `os.Root`を開いたまま`os.RemoveAll`すると失敗する（`Init`が失敗したときの後片付けで、実際にCIのWindowsだけで起きた）。**先に`Close`してから消す。** 後片付けの失敗を握りつぶさない（握りつぶすと、作りかけが残り、次の実行が「すでにある」と断る連鎖になる）
