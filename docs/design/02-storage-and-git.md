# mtqg 設計：配置とgit

> 設計時点の判断と、その理由の記録。**現在の仕様は `docs/reference/` が正**であり、食い違う場合は reference に従う。節番号（§N.N）は設計文書全体で通し番号になっている。

## 4. 配置とgit

### 4.1 `.mtqg/`は普通のファイルとしてgit管理対象にする

- プロジェクト内のディレクトリ（`.mtqg/`）にデータ化される
- **`.mtqg/`はgit管理対象に含める**。`.gitignore`すべきではない
  - チームで共有できる
  - AIがリポジトリを開いた瞬間に経緯を把握できる
  - ローカルのみだと経緯自体が失われるリスクがある
- 共有・版管理・合流は、他のファイルと同じくgitに任せる（2.1）

ディレクトリ構成の案：

```
.mtqg/
  .gitattributes        # 改行コード固定と merge=union の指定（7.4）
  version               # データ形式の番号。1行に数字だけ（5.6）
  SCHEMA.md             # データ形式の仕様（5.3）
  journal.jsonl          # すべてのイベントを1ファイルに追記する（7.4）
  archive/              # アーカイブした項目の行（9.1）
    2021-01-01..2024-09-18.jsonl
```

### 4.2 ブランチとの関係（決定）

**記録は他のファイルと同じくブランチに属する。**

- featureブランチで書いたmemoやqaは、マージされるまで他ブランチから見えない
- ブランチを捨てれば、記録も一緒に消える

ブランチの扱いはgitの利用者が選ぶことであり、mtqgが別の保存場所で救うことはしない（2.1）。捨てるブランチの知見を残したければ、利用者がそのファイルをマージやcherry-pickで持ち込めばよい。これもgitの操作である。

（旧案の「専用refでブランチ横断にする」は、git運用に負荷をかけ、版管理の領域に踏み込むため採らない。2.7）

### 4.3 gitの運用には何も要求しない

**mtqgはgitを読むことはあっても、gitの運用には何も要求しない。** gitは「記録を運ぶ乗り物」としてだけ使い、運転の仕方には関与しない。導入のたびにコミット規約やフック設定を求める道具は、それ自体が1.6の「使わずに済ませられてしまう」原因になるため。

- mtqgはコミット、push、フックの設定など、gitへの書き込みを自分からは行わない（`.git/`の中に自分用のディレクトリ`mtqg/`を置くことは、gitの動きを変えないのでこれに当たらない・6.4）
- コミットメッセージの書き方や、コミットのまとめ方を要求しない
- gitフックを必須にしない
- `.mtqg/`は普通のファイルとして、好きなタイミングで、好きなまとめ方でコミットすればよい

独立させても残る負荷：

- **記録をコミットし忘れると共有されない**：`mtqg status`で未コミットの記録の件数を見られるようにし、AIエージェントには`context`の中で伝える。後押しはmtqg側の表示にとどめる

### 4.4 `.mtqg/`の探し方と作り方（決定）

gitの探し方（カレントディレクトリから上にたどり、最初に見つかった`.git`を使う）を土台にする。

**探し方**

カレントディレクトリから親へ1つずつたどり、各ディレクトリで次の順に確認する。

1. `.mtqg/`があれば、それを使う
2. `.git`があれば（ディレクトリでもファイルでもよい。worktreeやサブモジュールではファイル）、そこがリポジトリの境界。`.mtqg/`はまだ無いので、**「`mtqg init`を実行してください」と案内して終了する**

- 同じディレクトリに両方ある場合（普通のリポジトリのルート）は、`.mtqg/`を先に確認するので、そのまま使われる
- リポジトリの境界（`.git`）より上には行かない。リポジトリの外にある無関係な`.mtqg/`を拾わない（gitの`GIT_CEILING_DIRECTORIES`の役割を、境界が自動で果たす）
- `.git`にも`.mtqg/`にも当たらずにファイルシステムのルートまで来たら、「gitリポジトリの中で実行してください」と案内する。mtqgはgitを前提にしている（記録元IDとカウンタを`<git-dir>/mtqg/`に置く・6.3）
- サブモジュールは独自の`.git`を持つので、gitと同じく親とは別の`.mtqg/`になる
- 探索を使わずに場所を指定する方法として、gitにならい`mtqg -C <パス>`を用意する（そのパスから探し始める）

**作り方：`mtqg init`は必ず明示的に実行する**

- 読むコマンドでも書くコマンドでも、`.mtqg/`を**自動では作らない**。cloneしただけのリポジトリや関係ないリポジトリに`.mtqg/`が生えることを防ぐ
- `mtqg init`は、**どこで実行しても**上と同じようにたどる
  - `.git`に当たったら、**その隣（リポジトリのルート）に`.mtqg/`を作る**
  - 途中で`.mtqg/`に当たったら、**エラー**（「すでにあります：<パス>」）。上書きも二重作成もしない
- サブディレクトリで実行しても必ずルートに作られるので、「うっかり記録が分かれる」事故が起きない
- 結果として、**`.mtqg/`は1つのgitリポジトリに1つ**になる。モノレポでサブプロジェクトごとに記録を分ける使い方は、今は用意しない（必要が出たら検討する）
